# 특징점·정합 분석

## 실행

```powershell
./build/Release/fp_inspect.exe RUN_FOLDER NEW_OUTPUT_FOLDER 12
./build/Release/fp_inspect.exe --verify RUN_FOLDER
```

RUN_FOLDER에는 plan.tsv, pairs.tsv, provenance.json, templates/, tasks/가 있어야 한다. 현재 자체 minutiae-v2 특징량만 지원한다. 기존 방향장 알고리즘이나 다른 회사의 불투명 템플릿에는 적용할 수 없다.

숫자는 각 범주에서 선택할 최대 쌍 수(1~100, 기본 10)이다. 처리 실패, 정상 반환 중 낮은 본인 점수, 정상 반환 중 높은 타인 점수를 각각 별도로 선택한다. 임계값을 맞춰 오인식 여부를 새로 판정하지 않는다. 출력 폴더를 덮어쓰지 않는다.

생성된 index.html을 브라우저에서 연다. 별도 서버·인터넷 연결·Node/Python 런타임은 필요 없다. PNG를 별도 파일로 보관하며, 브라우저의 로컬 파일 보안 정책 때문에 그림 저장이 막히지 않도록 표시 이미지도 HTML에 포함한다. 따라서 보고서에는 지문 이미지와 특징점이 포함된다.

Windows GUI에서는 시험 완료 후 `특징점·정합 분석` 버튼으로 실행한다. 생성 작업은 백그라운드에서 수행하고, 중단 요청은 분석 출력 폴더의 cancel.request로 전달한다. 중단된 분석에는 최종 HTML을 생성하지 않는다. 네이티브 GUI 연결은 빌드 완료 상태이며 실제 클릭 검증은 남아 있다. CLI와 생성된 브라우저 화면은 검증했다.

## 화면

- 원본 나란히: 각 이미지의 특징점·방향과 알고리즘이 선택한 대응선을 표시한다.
- 정합 후 겹쳐 보기: 등록 이미지를 선택된 강체 변환으로 비교 좌표계에 옮긴다. 비교 이미지 바깥은 잘린다.
- 대응 표: 최종 가중치, 위치 잔차, 방향 잔차. 표의 행을 누르면 해당 대응을 강조한다.
- 추출 품질 필터: 표시만 바꾼다. 인식 점수나 정합을 재계산하지 않는다. 품질값은 확률이 아니다.
- PNG 저장: 현재 보기의 그림을 저장한다.
- 처리 실패는 정합을 그려내지 않으며, 유효한 가설이 없는 점수 0도 기본 단위 변환을 정답처럼 보여주지 않는다.

## 근거와 검증

시험 목록 SHA-256과 선택한 원본 이미지 SHA-256을 확인한다. 템플릿 크기·버전·체크섬을 검사한다. 정상 비교는 현재 코드로 재현한 점수와 원본 점수가 1e-12 이내로 일치해야 한다. 맞지 않으면 다른 알고리즘 버전의 결과를 그린 것으로 간주하고 중단한다.

`--verify`는 이미지 보고서를 쓰지 않고 전체 정상 비교에서 진단 기능을 켠/끈 점수, 기록된 점수, 일대일 대응과 위치 잔차를 대조한다. 실패 기록은 그대로 유지한다. 이 모드는 기존 캐시의 수치 회귀 검사이며 이미지 출처 검사는 HTML 생성 경로에서 수행한다.

기존 세 원본 실행의 정상 2,360쌍에서 점수가 일치했고 실패 10쌍을 유지했다. 합성 회전/이동의 변환·대응 추적도 검증했다. 변경된 목록·원본 이미지, 손상 템플릿, 점수 불일치가 거부되는지 원본과 분리한 테스트 복사본으로 검사했다.

브라우저 검사에서는 실패 상태, 본인/타인 탐색, 정합 보기, 대응 선택, 표시 필터의 점수 불변, 검색, PNG 내보내기를 확인했다. 개발용 검사는 tests/inspect_browser.cjs(Playwright 필요), tests/inspect_integrity.py(Python 표준 라이브러리)이다. 프로그램 사용 자체에는 이 도구들이 필요 없다.

## 해석의 한계

대응선은 알고리즘이 선택한 가설이다. 사람이 주석한 정답 특징점 대응은 아니다. 본인/타인 지문 라벨만으로 각각의 대응점이 맞는지는 확정할 수 없다.

좌표는 현재 500dpi 입력에서 픽셀 좌표로 표시한다. 이미지 영역 밖의 점이 있으면 경고한다. 잡음 시험은 기록된 조건과 시드로 비교 이미지를 재생성하므로 같은 난수·변형 구현이 필요하다. 기존 캐시를 현재 DLL로 다시 추출해서 바꾸지는 않는다.

이 기능은 관찰을 돕는 것이며 알고리즘의 정확도 개선이나 일반화 검증을 의미하지 않는다. 선택된 사례를 보고 상수를 바꾸는 경우 개발 이력을 기록하고 별도의 미관측 검증을 유지해야 한다.
