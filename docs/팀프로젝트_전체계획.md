## 2. 입력 자료 분석

### 2.1 테스트 DB (각 zip, 8-bit grayscale TIFF)

| DB | iType | 해상도(W×H) | 구성 | 파일명 규칙 |
|---|---|---|---|---|
| FVC2000_DB3_B | 1 | 448 × 478 | 10손가락 × 8장 = 80장 | `{손가락ID}_{순번}.tif` (101_1 ~ 110_8) |
| FVC2002_DB3_B | 2 | 300 × 300 | 10 × 8 = 80장 | 동일 |
| FVC2004_DB1_B | 2 | 640 × 480 | 10 × 8 = 80장 | 동일 |

- 평가 프로그램은 TIFF를 디코딩하여 **헤더 없는 raw 픽셀 버퍼(1byte/pixel, 좌상단부터)** 로 DLL에 전달해야 한다.
- ⚠️ **확인 필요 (교수님 질의):** FVC2002_DB3_B와 FVC2004_DB1_B는 iType이 둘 다 2인데 해상도가 다르다. DLL 함수에는 이미지 크기 인자가 없으므로, DLL이 크기를 알 방법을 확정해야 한다. (예: iType별 크기 표를 새로 받기 / 평가 시 iType 값을 별도로 지정 / DLL이 크기를 추정) → **1주차 내 질의**.

### 2.2 DLL 규격 (K-NBTC 안내서 p26–29, 예제 `BioApi.h`)

```cpp
extern "C" __declspec(dllexport)
int KISA_Enroll (int iType, unsigned char* pImage, unsigned char* pEnroll,
                 int* piEnrollSize, int* piErrorCode, char arErrorMessage[256]);
int KISA_Attempt(int iType, unsigned char* pImage, unsigned char* pAttempt,
                 int* piAttemptSize, int* piErrorCode, char arErrorMessage[256]);
int KISA_Compare(unsigned char* pEnroll, unsigned char* pAttempt,
                 double* pdScore, int* piErrorCode, char arErrorMessage[256]);
```

- 반환값: 성공 1, 실패 0 이하 → 실패 시 에러코드/메시지를 로그에 기록
- 템플릿 크기 **< 1,000,000 byte**, 점수는 **0(타인)~1(동일)**, 소수 셋째 자리까지 표현
- 범위 밖 점수는 **비교 거부(FNMR 영향)** 로 판정
- `KISA_Compare`에는 템플릿 크기가 전달되지 않음 → **템플릿은 자기기술적(헤더에 크기·버전 포함)** 이어야 함
- 부속 파일은 DLL과 같은 폴더에 두고 `GetModuleFileName(g_hDLL)`로 경로 획득 (안내서 p31)
- 예제 DLL은 VC2005/2010 프로젝트로, **32bit(x86)** 일 가능성이 높음 → 평가 프로그램은 x86/x64 DLL을 모두 로드할 수 있어야 함(아래 4.2)

### 2.3 시험 조합 규모 (DB 1개 기준, 동일 이미지 비교 제외)

| 규칙 | 계산 | 시도 수 |
|---|---|---|
| 본인비교 – 모든 조합(순서 있음) | 10 × 8 × 7 | 560 |
| 본인비교 – 모든 조합(대칭 제거, FVC 방식) | 10 × C(8,2) | 280 |
| 타인비교 – 모든 조합 | 80 × 72 | 5,760 |
| 타인비교 – 각 손가락 첫 1장끼리 (FVC 방식) | 10 × 9 (대칭 제거 시 45) | 90 |

→ 규모가 작아 전수 평가도 수 초~수 분 수준. 다만 실제 K-NBTC DB(7,500장/센서)를 감안해 **병렬·부분 평가 구조**를 갖춰야 한다.

### 3.2 성능 리포트 항목 (PDF p7–p10)

| 항목 | 정의 |
|---|---|
| FTE | N_EF / N_Enroll (FAIL·Timeout·Crash 포함, **횟수도 기재**) |
| REJ_genuine | N_G,MF / N_G,match attempted |
| REJ_impostor | N_I,MF / N_I,match attempted |
| FMR(t) | N_I,s≥t / N_I (N_I: 사전 정의된 전체 impostor 시도 수) |
| FNMR(t) | (N_G,EF + N_G,MF + N_G,s<t) / N_G |
| EER | FMR(t)=FNMR(t)인 t가 있으면 그 값, 없으면 t1, t2 기반 추정(FVC 방식: 중간값이 작아지는 쪽) |
| EER* | 알고리즘이 OK로 반환한 점수만으로 계산한 EER (FTE·실패가 없으면 EER과 동일) |
| ZeroFMR | FMR = 0% 에서의 최저 FNMR |
| ZeroFNMR | FNMR = 0% 에서의 최저 FMR |
| FMR100 / FMR1000 | FMR ≤ 1% / ≤ 0.1% 에서의 최저 FNMR |
| Enrollment time | 평균 등록 시간 |
| Matching time | 평균 비교 시간 (전체 / genuine / impostor) |
| Template size | 템플릿 크기 평균·최대 |
| 그래프 | **DET Curve**(log-log, EER·FMR100·FMR1000 표시), **Score Distribution**(genuine/impostor 히스토그램), **FMR(t)·FNMR(t) 곡선**(EER 지점 표시) |

**EER 추정(FVC 정의)**
- t1 = max{ t | FNMR(t) ≤ FMR(t) }, t2 = min{ t | FNMR(t) ≥ FMR(t) }
- FMR(t1)+FNMR(t1) ≤ FMR(t2)+FNMR(t2) 이면 [EER_low, EER_high] = [FNMR(t1), FMR(t1)], 아니면 [FMR(t2), FNMR(t2)]
- EER = (EER_low + EER_high) / 2

### 4.2 전체 구조 — **프로세스 격리 구조**

평가 대상 DLL이 crash하거나 무한루프에 빠져도 평가 프로그램이 죽지 않아야 하므로, **DLL은 별도 Worker 프로세스에서만 로드**한다.

```
┌──────────────────────────── FPEval.exe (GUI, 64bit) ────────────────────────────┐
│  UI 계층(MFC)  ─  설정(EvalConfig)  ─  시나리오 생성(PairGenerator)             │
│        │                                   │                                    │
│  진행 표시/중지 ◄── EvalScheduler ──────── Job Queue (등록 → 비교, 무작위 순서)  │
│                        │  (Worker N개 관리, timeout 감시, 재시작)               │
│  ResultStore(로그 CSV) ◄┘                                                       │
│  MetricsCalculator → ReportBuilder(HTML/DOCX) + ChartRenderer(SVG/EMF)          │
└────────────────────────────────┬────────────────────────────────────────────────┘
                                 │ Named Pipe (요청/응답) + 공유 폴더(이미지/템플릿)
           ┌─────────────────────┼─────────────────────┐
     FPWorker32.exe #1     FPWorker32.exe #2  …   (DLL bitness에 맞춰 32/64 선택)
     LoadLibrary(DLL)      LoadLibrary(DLL)
     KISA_Enroll/Attempt/Compare 호출 + 시간 측정 + 가드 검사
```

- **Timeout:** Scheduler가 작업별 마감 시각을 감시 → 초과 시 `TerminateProcess` 후 해당 작업을 TIMEOUT 기록, Worker 재기동
- **Crash:** Worker 종료 감지(파이프 끊김/`WaitForSingleObject`) + Worker 내부 SEH(`__try/__except`)로 예외 코드 기록 → CRASH
- **강제 종료:** 중지 버튼 → 모든 Worker 종료, 지금까지 결과는 보존(이어하기 가능)
- **병렬:** Worker 개수 = 사용자 지정 동시 수행 수
- **DLL bitness 자동 판별:** PE 헤더(Machine 필드)를 읽어 x86/x64 Worker 선택

### 4.3 "출력-동작 불일치" 감지 규칙

| 상황 | 판정 |
|---|---|
| 반환 1인데 `*piEnrollSize` ≤ 0 또는 ≥ 1,000,000 | MISMATCH (등록 실패 처리) |
| 반환 1인데 점수가 NaN 또는 [0,1] 범위 밖 | MISMATCH (비교 거부 처리) |

| 같은 입력에 대해 결과가 달라짐 (선택 옵션) | 일부 쌍 재실행으로 결정성 검사 |

## 5. 지문인식 알고리즘(DLL) 계획

### 5.1 처리 파이프라인 (미뉴셔 기반)

1. **크기 결정**: iType → (W, H) 표 (2.1의 확인 결과 반영)
2. **전처리**: 정규화(평균·분산), 블록 단위 전경 분할(segmentation)
3. **방향장(orientation field)**: gradient 기반, 블록 평활화 / **주파수 추정**
4. **Gabor 필터 강조** → 이진화 → **세선화**(Zhang–Suen)
5. **미뉴셔 추출**: Crossing Number(끝점·분기점) + 위치·방향·품질
6. **거짓 미뉴셔 제거**: 경계 근처, 짧은 가지, 너무 가까운 쌍 제거
7. **템플릿**: `[magic|version|W|H|count|minutiae…]` 직렬화 (수 KB, 1MB 제한 여유)
8. **매칭**: 미뉴셔 쌍 기반 정렬(Hough 투표로 회전·이동 추정) → 허용 오차 내 대응점 수 → 0~1 점수 정규화(소수 3자리)
9. (성능 개선 단계) 로컬 디스크립터(MCC 계열) 또는 이웃 미뉴셔 구조 기반 매칭으로 교체/병합

### 5.2 품질 기준

- 어떤 입력에도 crash 없음 (버퍼 경계 준수, 예외 안전), 실패 시 0 반환 + 의미 있는 에러코드
- 스레드 안전(전역 상태 없음) → 병렬 평가 대응
- 부속 파일 미사용(단일 DLL) 원칙, 필요 시 DLL 경로 기준 로딩
- x86/x64 두 가지로 빌드
- 목표(내부): 3개 DB 평균 EER 10% 이하 → 개선 단계에서 5% 이하

### 5.3 시험용 "불량 DLL" (평가 프로그램 검증·시연용)

| DLL | 동작 |
|---|---|
| `Dummy_OK.dll` | 안내서 예제 그대로(고정 점수 0.8) — 파이프라인 검증 |
| `Bad_Crash.dll` | 일정 확률로 NULL 접근 |
| `Bad_Timeout.dll` | 일정 확률로 무한 루프 |
| `Bad_Score.dll` | 1.5 / -0.1 / NaN 점수 반환 |
| `Bad_Size.dll` | 템플릿 크기 0 또는 2,000,000 보고 / 버퍼 오버런 |
| `Bad_Random.dll` | 무작위 점수 → EER≈50% 확인용 |

→ 중간·최종 시연에서 "오류 감지" 기능을 직접 보여줄 수 있음.
