1프로젝트 개요

목표C/C++로 Windows 응용프로그램을 개발하고 설치 패키지 배포까지 SW 개발 전 과정 수행
팀3인 1팀 (총 6팀)
산출물① 지문인식 알고리즘 평가 프로그램 (Windows GUI)
② 지문인식 알고리즘 (Windows DLL, K-NBTC KISA_Enroll / KISA_Attempt / KISA_Compare 규격)
제약C/C++만 사용. 공개 라이브러리는 단위 기능에 한해 허용(출처 명시). 독자 동작 SW 연동 불허
배점평가 SW 70% · 알고리즘 인식 성능 20% · 발표/자료/시연 10% · 팀원 평가 ±
일정12주 진도 보고 · 13주 중간 시연 발표 · 14주 진도 보고 · 15주 최종 발표·시연
시험 DBFVC2000_DB3_B (iType 1, 448×478) · FVC2002_DB3_B (iType 2, 300×300) · FVC2004_DB1_B (iType 2, 640×480) — 각 10손가락 × 8장

4.3Worker 검사 규칙 (src/worker/CommandExecutor.cpp)

  • 입력 가드 페이지: 이미지·템플릿 버퍼의 끝을 PAGE_NOACCESS 페이지 바로 앞에 둔다. 1바이트라도 넘어 읽으면 Access Violation
  • 출력 canary: 출력 버퍼 1,000,000 바이트 뒤 4,096 바이트를 0xCD로 채우고 호출 후 검사
  • SEH: DLL 호출만 __try/__except로 감싸 예외 코드를 기록
  • 시간: QueryPerformanceCounter로 DLL 호출 구간만 측정 (µs)
  • 오류 대화상자 억제: SetErrorMode, _set_abort_behavior → 크래시 시 창이 떠서 멈추지 않음
  • DLL 로드: LoadLibraryEx(LOAD_WITH_ALTERED_SEARCH_PATH) → DLL 폴더의 부속 DLL 탐색 (안내서 p31)

4.4Scheduler (src/core/exec/)

  • 슬롯 N개가 각자 스레드에서 "작업 꺼냄 → 요청 → 응답 대기 → 기록"을 반복. 응답 대기는 overlapped I/O + WaitForMultipleObjects(응답, 취소)
  • Worker 시작 + DLL 로드(Hello)는 최대 3번 재시도. 계속 실패하면 DLL 자체 문제로 보고 전체 중단
  • CRASH·TIMEOUT 후에는 Worker를 새로 띄운다 (망가진 DLL 상태 재사용 금지)
  • 모든 Worker는 Job Object(KILL_ON_JOB_CLOSE)에 들어가, 평가 프로그램이 죽으면 함께 종료
  • 중지: 새 작업 배분만 멈춤 / 강제 종료: 취소 이벤트로 즉시 Worker 종료
  • STEP 3과 STEP 4 사이에 barrier: 모든 템플릿이 만들어진 뒤 비교 시작
시간 제한값
Worker 파이프 연결10 s
DLL 로드 (Hello)15 s
작업 1건 (설정)기본 10 s
QUIT 후 종료 대기2 s

FNMR(t)(N_G,EF + N_G,MF + #{genuine 점수 < t}) / N_G — SKIP_AF는 MF에 포함
EERFVC 방식: t1 = max{t | FNMR ≤ FMR}, t2 = min{t | FNMR ≥ FMR}, 합이 작은 쪽의 [low, high] 중간값. 정확한 교차가 있으면 그 값
EER*OK 점수만으로, 분모도 OK 건수로 계산한 EER
ZeroFMR / ZeroFNMRFMR=0에서 최저 FNMR / FNMR=0에서 최저 FMR (없으면 "정의 불가")
FMR100 / FMR1000FMR ≤ 1% / ≤ 0.1%에서 최저 FNMR
시간OK 건의 평균·최대 (등록, 비교 전체·genuine·impostor)
템플릿 크기등록 OK 건 평균·최대

임계값 후보: 모든 점수의 고유값 + 0 + (1+ε). 정렬 배열에 이진 탐색. 그래프용 FMR/FNMR 곡선은 0.001 간격 1,001점.

수식 선택 옵션: EER 방식 FVC | Nearest, 분모 predefined(계획된 전체 시도) | attempted(등록 실패분 제외).
