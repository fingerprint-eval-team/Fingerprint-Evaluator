# Fingerprint-Evaluator 에이전트 워크플로 가이드

실제 저장소는 `Fingerprint-Evaluator/`다. 이 위치에서 현재 브랜치와 `git status --short`를 확인하고 기존 변경을 보존한다. `develop`은 통합 대상이다. 작업 시작 시 브랜치를 자동 전환하지 않지만, 커밋은 README 규칙의 작업 브랜치(`feature/`·`fix/`·`docs/`)에서 하며 `develop`에 직접 커밋하지 않는다.

초기 계획의 GoogleTest·miniz·`dev`와 현재 자체 `CoreTests`·`ZipWriter`·`develop`을 구분한다. 계획서의 JSON 예제를 실행 설정으로 복사하지 말고 `testdb/base.json`과 `EvalConfig`의 현재 직렬화를 확인한다. 과거 테스트 검사 수와 EER은 이번 변경의 검증 결과가 아니다.

## 변경별 검증 선택

검증 명령과 판정 기준은 [프로젝트 스킬 선택표](SKILLS.md)에서 연결하는 각 SKILL.md를 따른다. 문서마다 명령을 중복 관리하지 않는다.

| 변경 | 필요한 확인 |
| --- | --- |
| 문서·스킬만 | 로컬 링크·명령의 소스 대조, 두 스킬 사본 동기화, 공백 오류 |
| C++·CMake·Windows 리소스 | `fpeval-verification`: Win32/x64 빌드, x64 CoreTests |
| 스타일 정리(컨벤션 적용) | 기본 검증. 동작 변경과 커밋을 분리하고, 평가 경로를 건드렸으면 같은 조건 전후 실행 결과가 같은지 확인 |
| 알고리즘·평가 규칙·지표 | 기본 검증 + `fpeval-algorithm-experiments`·`fpeval-metrics-validation`: 동일 조건의 기준/변경 실행, 지표 변경은 소형 수치 사례 |
| Worker·스케줄러·로그·재개 | 기본 검증 + `fpeval-systematic-debugging`·`fpeval-concurrency`·`fpeval-resume-validation`: 해당 오류 DLL, 동시성·재개·상태 집계 |
| MFC UI | 기본 검증 + `fpeval-mfc-ui`: 실제 창의 배치·키보드·실행 상태 |
| 리포트·그래프 | 기본 검증 + `fpeval-report-generation`·`fpeval-chart-validation`: HTML/DOCX·SVG/EMF, 항목 선택·재생성 |
| 설치·배포 | `fpeval-release-validation`: Release 패키지와 깨끗한 Windows VM |

검증 기록에는 구성, 명령, 실제 결과와 실행하지 못한 항목을 적는다. 현재 CMake는 CTest를 등록하지 않으므로 CoreTests 실행 파일을 직접 호출한다. MFC·FVC DB·Word·VM 가용성은 작업 환경마다 확인한다.

## 스킬 관리

프로젝트 전용 스킬 18개는 `.agents/skills/`와 `.claude/skills/`에 동일한 절차를 둔다. `docs/SKILLS.md`는 선택표이며 원문 커밋·라이선스·조정 이유는 [공개 스킬 조사](skill-sources/README.md)에 기록한다. 수정할 때 이름·설명·상대 링크·앵커와 두 사본의 일치를 확인한다. 이 구조에서는 별도 의존성이나 설치가 필요 없는 문서 절차를 우선 유지한다.

외부 스킬·플러그인은 세션의 도구 목록과 실제 설치 상태를 확인한 뒤 선택한다. 특정 에이전트의 `/debug`, `/verify`, `/code-review`가 모든 환경에 내장되어 있다고 가정하지 않는다. 프로젝트의 `fpeval-verification`과 외부의 동명·유사 명령을 구분한다. 과제 문서·발표자료 작성에 문서 도구를 쓸 수 있지만, 앱이 생성하는 리포트의 검증은 프로젝트 출력 파일을 기준으로 한다.

## MFC GUI 디자인 리소스

현재 구현은 `FPEval.rc`의 대화상자 리소스와 네 탭, `MainDlg.cpp`·`Pages.cpp`의 메시지 맵·DDX로 구성된다. 화면 변경은 이 구조를 유지하며 진행한다. [리소스](../src/gui/FPEval.rc) · [메인 창](../src/gui/MainDlg.cpp) · [탭 페이지](../src/gui/Pages.cpp)

- 대기·실행 중·완료 화면을 같은 창 크기로 비교한다. 오류·중지·이어하기를 바꿨으면 그 상태도 확인한다.
- 평가 시작, 중지, 강제 종료의 의미를 구분하고 설정 작업과 결과 열기 동작을 알아보기 쉽게 배치한다.
- 긴 한글 경로, 100%·125%·150% 배율, Tab 순서·포커스, 실행 중 설정 잠금을 확인한다. 확인하지 못한 배율은 기록한다.
- 아이콘은 한 계열로 맞추고 버튼에는 동작을 설명하는 문구를 함께 둔다. 외부 에셋은 채택 시 원본 라이선스와 배포 고지를 확인한다. 앱 아이콘은 여러 크기의 `.ico`와 `.rc` 리소스 연결을 확인한다.
- 실제 화면 조작이 가능한 도구가 제공되면 해당 도구의 지침을 읽고 사용한다. 정적 리소스 검토와 실행 화면 검증을 구분한다.

## CI 도입 시

현재 저장소에는 Windows 빌드 워크플로가 없다. CI를 추가할 때는 C++·MFC와 호환 CMake가 설치된 Windows 러너에서 `build.ps1` 종료 코드를 확인한 다음 x64 CoreTests를 실행한다. 러너 이미지와 액션 버전은 도입 시 공식 문서에서 확인한다. FVC 실데이터·Word 화면·깨끗한 VM 설치 검증은 별도로 기록하고, CI 통과로 대체하지 않는다.
